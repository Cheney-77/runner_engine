模块以 FastAPI 应用为入口（app.py），通过 `create_app` 装配 lifespan、健康检查与 `/v1/runtime-environments/*` REST API，并将 `BuildService` 实例挂在 `app.state.build_service` 上供路由访问。

内部按职责分层：
- 模型层 `model.py`：定义不可变 `RuntimeBuildSpec` dataclass，负责解析 locked packages、计算 lock sha256 与稳定的 `env_key`（schema+base_image+python_version+platform+lock_sha256+build_policy_version）。
- 构建层 `builder.py`：封装外部工具调用——`uv pip compile` 生成带 hash 的 `requirements.lock`；内嵌 `RUNTIME_DOCKERFILE` 通过 `docker buildx build --push` 产出镜像，并从 metadata 中取 `containerimage.digest`；`verify_runtime_image` 在容器内用 `importlib.metadata` 校验已安装包集合。
- 存储层 `store.py`：`BuildStore` 使用 `psycopg_pool.ConnectionPool` 管理 PostgreSQL 连接，DDL 集中在 `BUILD_SCHEMA_STATEMENTS`（`runtime_environments`、`runtime_env_aliases`、`build_jobs` 三张表），并通过 `ON CONFLICT ... DO NOTHING` 实现幂等创建；`find_smallest_superset` 借助 JSONB `@>` 操作符做超集匹配并按 `package_count, created_at` 排序。
- 业务编排 `service.py`：`BuildService.resolve` 先尝试 exact 命中，再回退到 superset 复用（受 `allow_superset_reuse` 控制），然后 claim 构建任务 → 调 `build_runtime_image` → `mark_verifying` → `verify_runtime_image` → `mark_ready`，异常统一落库为 FAILED。
- 生命周期扩展 `lifecycle_service.py`：`LifecycleBuildStore` 继承 `BuildStore`，通过 `_init_schema` 追加 `lifecycle_state/last_used_at/retired_at/artifact_deleted_at/cleanup_error` 列及索引，重写 `get_for_request/find_smallest_superset/bind_request/claim_build` 以过滤 ACTIVE 状态；`LifecycleBuildService` 再组合 `BuildLifecycle` 提供 retire / cancel_retirement / delete_artifact 等管理接口。
- 路由扩展 `lifecycle_routes.py`：通过 `install_build_lifecycle_routes(application)` 挂载生命周期管理端点，与基础构建 API 共存于同一 FastAPI 实例。

依赖方向单向：app → service/lifecycle_service → builder/store/model/harbor，HTTP 层不直接访问数据库或外部工具。
