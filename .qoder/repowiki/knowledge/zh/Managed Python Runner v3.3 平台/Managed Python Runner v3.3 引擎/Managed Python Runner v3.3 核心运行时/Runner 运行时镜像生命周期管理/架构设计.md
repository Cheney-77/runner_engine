模块由三层组成：
- 持久层 `lifecycle_store.py`：通过 `psycopg_pool.ConnectionPool` 维护 `runner.runtime_image_lifecycle` 表，以 `sha256(image_ref)` 作为 `runtime_id` 主键，暴露 `begin_retirement` / `cancel_retirement` / `finalize_retirement` / `get_by_*` / `list_recent` 等原子 SQL 接口。
- 服务拦截层 `lifecycle_service.py`：`LifecycleRunnerService` 继承 `RunnerService`，在 `acquire_lease` / `renew_lease` / `invoke` 三个入口调用 `_assert_runtime_active`，将 RETIRING/RETIRED 映射为 `RUNTIME_RETIRING`（可重试）或 `RUNTIME_RETIRED` 错误，关闭租约级竞态。
- 运行时控制层 `lifecycle_runtime.py`：`LifecycleWorkerPool` 扩展 `WorkerPool`，在 `acquire` 中加 `RLock` 检查 `is_blocked_runtime` 并统计每个 runtime 的并发 acquiring 计数；新增 `retire_runtime` / `retire_idle_worker` 直接销毁空闲 worker。`RunnerLifecycleController` 聚合 service/pool/lifecycle/catalog/db，实现 `begin/cancel/finalize_runtime_retirement`、`runtime_image_status`（综合活跃调用、空闲 worker、acquiring 计数、后端托管 sandbox 列表判断 `safeForArtifactDeletion`）以及 `runtime_snapshot`。`LifecycleOpenSandboxBackend` 通过 OpenSandbox API 分页拉取带 `managed-by=runner` 标签的沙箱，用于最终清理判定。
依赖方向单向：service → store；controller → service + pool + lifecycle；pool 仅反向读取 lifecycle 的阻塞标记，避免循环依赖。
