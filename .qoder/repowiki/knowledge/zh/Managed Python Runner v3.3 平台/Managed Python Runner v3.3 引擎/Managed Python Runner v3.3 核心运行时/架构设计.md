app.py 作为唯一入口，按固定顺序组装三层组件：
- 接入层：publisher_gateway 的 Catalog + AccessControl 通过 gRPC serve() 暴露 mTLS 接口；admin_http 提供可选的生命周期管理 HTTP。
- 业务编排层：service.RunnerService（含 LifecycleRunnerService）负责租约生命周期、RunRequest 指纹/属性校验、幂等缓存、ActiveRun 内存表与后台 reaper 线程；policy.load_policies 注入安全策略。
- 执行层：pool.Quota + lifecycle_runtime.LifecycleWorkerPool 基于 backend（默认 opensandbox）获取 Worker，再经 worker.child 启动独立进程执行 Operator，并通过 http_api 与 path_virtualization 完成进程间通信与路径虚拟化。
- 持久化层：state.RunnerDB 统一持有 PostgreSQL 连接，被 service 与 lifecycle_store 共享，承载 lease、idempotency、run 审计与运行期状态机。
所有跨子模块依赖在 app.main 中集中装配，外部仅通过 gRPC 或 Admin HTTP 访问。
