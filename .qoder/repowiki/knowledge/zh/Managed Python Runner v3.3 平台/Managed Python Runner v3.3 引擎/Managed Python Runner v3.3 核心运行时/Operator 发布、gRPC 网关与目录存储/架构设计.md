模块由三个职责清晰的子层组成，依赖方向单向：publisher → catalog ← gateway。
- `catalog.py` 提供 `Catalog` 类，作为 Operator 发行版的单一持久化源，按 `{release_id}/operator.tar.gz + release.json` 布局落盘，通过临时文件 + `Path.replace` 保证原子写入，并在重复保存时校验 `artifact_sha256` 防止冲突。
- `publisher.py` 暴露 `OperatorPublisher.publish`，读取项目根下的 `operator.yaml`，校验 entrypoint（`module:function` 格式）、input/output_attributes、OCI 镜像 digest，计算确定性 source hash 并生成 PAX+gzip 归档（mtime/uid/gid/mode 归一化），限制压缩后体积 ≤10 MiB，最终调用 `catalog.save` 返回 `OperatorRelease`；同时提供 CLI `main()`。
- `gateway.py` 通过 `serve()` 启动 mTLS gRPC 服务器，内部定义 `Servicer` 继承自 `runner_pb2_grpc.ManagedPythonRunnerServicer`，在 Health/AcquireLease/RenewLease/Invoke/Cancel/ReleaseLease 等 RPC 上先经 `_peer_identity` 提取 x509 证书 CN/SAN 作为身份，再交由 `AccessControl.from_json` 加载的租户/项目白名单进行鉴权，最后委派给 `RunnerService`；所有业务异常统一经 `_abort_runner_error` 映射为 `grpc.StatusCode`。
- 运行时 gRPC stub 通过 `from .generated import runner_pb2, runner_pb2_grpc` 延迟导入，缺失时抛出引导错误提示执行 `scripts/generate_proto.py`，避免构建期强依赖 proto 编译产物。
