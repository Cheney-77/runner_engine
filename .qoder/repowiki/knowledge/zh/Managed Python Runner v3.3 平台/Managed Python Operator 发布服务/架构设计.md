模块以 `app.py` 为 FastAPI 入口，通过 `create_app()` 装配路由并借助 `lifespan` 注入 `LifecyclePublishService`；业务编排集中在 `service.PublishService`，按职责拆分为：
- API 层：`app.py` 注册 `/v1/operators`、`/v1/edge/*`、`/v1/minio/*` 等 REST 端点，`lifecycle_routes.py` 通过 `install_publish_lifecycle_routes` 挂载 `/v1/admin/runner-runtimes/*` 管理员路由。
- 领域服务层：`service.PublishService` 组合 `PublishStore`(SQLAlchemy)、`LocalSourceStore`(源码快照)、`BuildServiceClient`(HTTP 调用 build_service)、`EdgeDependencyResolver`、`OperatorPublisher`，对外暴露 analyze/create_virtual_contract/compile_backend/publish_backend 等用例。
- 后端抽象：`backends/base.py` 定义 `backend_variant_key` / `backend_contract_sha256` 统一变体键与合约摘要；`backends/runner.py` 与 `backends/nifi_native.py` 分别实现 Runner 与 NiFi Native 两种后端的合约编译与产物写入，由 `backends/models.py` 中的 Pydantic 模型描述契约结构。
- Edge 打包：`edge_bundle.py` + `edge_dependencies.py` 负责按目标平台聚合依赖、生成锁文件与 zip bundle。
- 存储与配置：`store.py` 封装 SQLAlchemy 持久化（operator/contract/variant/job/edge bundle），`source_store.py` 基于目录快照实现不可变源码引用，`model.py` 与 `schema.py` 集中 Pydantic 请求模型，`build_client.py` 用 stdlib `urllib.request` 访问外部 Build Service。
依赖方向单向：API → service → backends/store/source_store/build_client/edge_*，不反向依赖。
